### 第 2 轮（02:55–03:00）**安全缺陷修复（重要）**
实测发现并修复 2 个真实安全漏洞：

| 漏洞 | 现象 | 修复 |
|---|---|---|
| **题目 flag 泄露** | 选手端 `PlayArena.vue` 直接调用管理端 `GET /challenges`，返回体含明文 `flag`，选手查看浏览器网络请求即可拿到答案 | 新增选手端专用接口 `GET /challenges/play`，返回 `PlayChallengeVO`（显式不含 flag/answer），前端改为调用该接口 |
| **越权读取答案** | PLAYER 角色持有 `question:view` 权限，仍可直接调用管理端接口拿到 `flag{666b582e...}` | 管理端接口权限点收紧为 `question:update`，并新增 `assertCanSeeFlag()` 双重守卫：仅 ADMIN/SUPER_ADMIN/PLATFORM_ADMIN/JUDGE 可获取含 flag 视图 |

**修复后实测**：
- 选手端 `/challenges/play`：返回字段 `['category','description','difficulty','id','score','title']`，**无 flag/answer**
- 选手访问管理端 `/challenges`：**403 缺少必要权限**
- 管理员访问管理端 `/challenges`：200，含 flag（功能正常）

### 第 31 轮 · 回归确认 + Redis 数据一致性修复（06:40–06:50）

**全量回归**：`83 / 83 通过`（04:44:04），第 30 轮兼容控制器无回归。

**发现的数据一致性问题（测试操作引入，非代码缺陷）**

为清除限流键执行了 `FLUSHDB`，导致 Redis 中的 AWD flag 与排行榜 ZSet 被一并清空。重建时按容器实际 flag（`_r7_`）写入，但**攻击校验口径取「当前 RUNNING 轮次」= r6**，两者轮次号不一致 → 攻击返回「flag 不正确或已过期」。

**根因分析**
- `AwdScoreService.verifyFlag()` 读取 `AwdKeys.flagOne(contestId, roundNo, teamId, questionId)`
- `roundNo` 由 `resolveRound()` 取「进行中轮次，否则最近一轮」→ 此时 RUNNING 的是 **r6**
- 手工重建时键写成了 `r7`（按容器 flag 的 `_r7_` 标识）→ 键不匹配

**修复与验证**
1. 把容器实际 flag 同步到 **r6** 键（与校验口径对齐）
2. 攻击闭环实测：`team1 → team2` → `code=0, success=True, +150, firstBlood=True`，提示「首杀！flag 正确」

**结论**：攻击链路代码本身正确，本次是**测试环境手工重建数据导致的键前缀不一致**；按运行轮次对齐后立即恢复。也侧面验证了 `verifyFlag` 严格按 `contestId + roundNo + teamId + questionId` 四元组定位，**不会跨轮次误判**。

### 12.2 根因（三个叠加缺陷）

| # | 缺陷 | 说明 |
|---|---|---|
| 1 | **tree-shaking 剪掉 API 函数** | `api/index.js` 里的 `loginByThird / wechatCallback / wechatStatus / wechatExchange / sendSmsCode / loginByPhone` 仅被 `authApi` 对象聚合导出，Vite 构建时判定为未使用而摇树删除。产物 chunk 内 `login-third`、`wechat/callback`、`sms-code` 出现次数均为 **0**，点击按钮调用 `authApi.loginByThird` 得到 `undefined` → 静默失败无任何提示 |

## 十四、二维码不显示的最终修复（11:26）

### 14.1 根因链（三个叠加）

| # | 缺陷 | 表现 |
|---|---|---|
| 1 | **`el-tab-pane` 懒渲染时序** | 切到「扫码登录」Tab 时 `canvas` 尚未挂载，`drawQr()` 拿到 `qrCanvas.value === undefined` 直接 return，二维码永远空白 |
| 2 | **遮罩层无条件覆盖** | `<div v-if="qrState" class="qr-mask">` 在 `WAITING` 状态下也渲染，白色半透明遮罩（`inset:10px`）盖住 canvas，只剩转圈动画 |
| 3 | **`qrContent` 未声明** | Tab 切换 watcher 中引用 `qrContent.value` 但变量不存在，抛 `ReferenceError` 中断重绘 |

### 14.2 修复

```js
// ① 遮罩只在非 WAITING 时显示
<div v-if="qrState && qrState !== 'WAITING'" class="qr-mask">

// ② canvas 挂载重试（最多 3s）
async function drawQr(content, retry = 0) {
  let c = qrCanvas.value
  if (!c) {
    if (retry < 30) { await sleep(100); return drawQr(content, retry + 1) }
    return
  }
  await QRCode.toCanvas(c, content, { width: 180, margin: 1, errorCorrectionLevel: 'M' })
}

// ③ 声明 qrContent 并保存
const qrContent = ref('')
qrContent.value = d.state

// ④ Tab 切到扫码页：先等 120ms 过渡结束再绘制
await new Promise(r => setTimeout(r, 120)); await nextTick(); drawQr(d.state)

// ⑤ el-tab-pane 显式关闭 lazy
<el-tab-pane label="扫码登录" name="qr" :lazy="false">

// ⑥ 进入页面即预取扫码会话（不等切 Tab）
onMounted(async () => {
  if (tab.value === 'qr') newQr()
  else setTimeout(() => { if (!qrSession.value) newQr() }, 600)
})
```
